# Lua tileset and tile compatibility

The scripting adapter can inspect and edit embedded tileset artwork without converting tilemap layers into raster layers. All placements of the edited tile update, including linked maps and other animation frames. The existing Lua worker, transaction replay, cancellation, memory/time bounds, and host commit path still apply.

| Supported API | Behavior |
| --- | --- |
| `sprite.tilesets` | One-based ordered array of Tileset handles. |
| `layer.tileset` | Read/write for embedded same-sprite tilesets. Assignment retains numeric map words, flags, positions and links, even when tile sizes differ. Assigning `nil`, or assigning on a non-tilemap layer, is a native-compatible no-op. Foreign or unresolved external resources fail explicitly. Reading a PixelWall layer that switches tilesets between frames remains an explicit compatibility error. |
| `#tileset`, `tileset:tile(index)` | Native count and zero-based lookup, including reserved tile zero. Out-of-range integer indices return `nil`. |
| `tileset:getTile(index)` | Deprecated native alias returning the same live Image as `tileset:tile(index).image`. |
| `tileset.name`, `tileset.baseIndex` | Writable metadata; name limited to 240 UTF-8 bytes without NUL, base index to signed 16-bit values. Empty names are retained. `baseIndex` does not renumber placements. |
| `tileset.grid`, `Grid()`, `Grid(grid)` | Read-only Grid values; copied `origin` Point and `tileSize` Size values. Default Grid is 16×16 at (0,0). |
| `tile.index` | Read-only zero-based index; a retained Tile handle stays at that numeric index after insertion/deletion. If it is beyond the new count, its index remains readable and its image is `nil`. |
| `tile.image` | Live Image, supporting the existing raster Image subset including pixels, packed bytes, clear, crop-copy, flip and drawing. Replacement requires the sprite color mode and exact declared tile size. Replacement invalidates the previous tile Image handle, as observed in Aseprite. |
| Tileset/Tile `data`, `color`, `properties` | Native text, color and properties, including named extension namespaces, through the existing bounded property codec. |
| `sprite.gridBounds` | Read/write sprite grid bounds. Default is 16×16. Stored origins are bounded to signed 16-bit coordinates. |
| `sprite:newTileset()` / `(GridOrRectangle[,count])` / `(sameSpriteTileset)` | Creates an embedded resource. No-argument creation uses the owner sprite grid dimensions with origin (0,0). Explicit constructor origins must be (0,0); count includes reserved tile zero. Copies preserve artwork/user data and grid origin; baseIndex and matching flags reset to native defaults. |
| `sprite:newTile(tileset[,index])` | Appends by default or inserts at indices 1 through count. New indexed tile storage contains raw zero, including when the sprite mask is another index. |
| `sprite:deleteTile(tile)` / `(tileset,index)` | Removes indices 1 through count minus one. Tile zero cannot be inserted/deleted. |
| `app.command.NewLayer{tilemap=true,name?,gridBounds?}` | Atomically creates a tileset and empty tilemap at the active layer/group, selects the layer and returns `true`. NewLayer does not create any tilemap cels. Other NewLayer options remain limited to the existing documented subset. |
| `sprite:deleteTileset(tilesetOrIndex)` | Deletes only a tileset unused by every layer/frame. The numeric overload is one-based. Deleted handles fail explicitly. |

Tileset writes check every referencing layer and its parents, including hidden layers. This is a PixelWall document-lock invariant; it is not a claim that all native Aseprite scripting operations enforce locks in the same way. Shared map images and native numeric tile IDs/flip bits remain unchanged. If unrelated tilesets or raster cels share the underlying artwork storage, the edited tileset receives its own copy; unrelated artwork remains unchanged. Independent editor tiles that share a source image are likewise separated when one tile is edited.

Imported tileset atlases expose their real tile zero, which can be painted and retains user data even when native empty-tile flags hide its placements. PixelWall-created tilesets have a virtual empty slot zero; its metadata is editable and persists at native index zero, but its artwork is read-only until it is represented by an embedded native atlas. Structural editing or assignment materializes editor resources as embedded native atlases, after which tile-zero artwork is writable. Other editor tiles use indices starting at one, matching their native export. Color-conversion variants retain separate indices and images across palette contexts.

Raw indexed writes preserve indices found in any effective frame palette; they do not change the palettes. Per-frame palette evaluation remains the renderer's responsibility. A script can inspect external tileset metadata, but it must obtain artwork through the host's explicitly selected external-resource embedding workflow before reading/editing Tile.image. Scripts receive no automatic file or network access.

Insertion and deletion follow the observed **native Lua API**, which leaves tilemap numeric words unchanged. Inserting at index 1 moves old artwork 1 to slot 2 while a placement of number 1 uses the inserted artwork. Deleting a slot exposes its successor; a map number beyond the remaining count renders empty and can become visible again if that slot is later appended. This is not the appearance-preserving reindex behavior of some editor commands. Native linked map image IDs and flags are retained; engine maps are converted to the equivalent native words before changing slots.

Tile handles stay bound to an index. Existing Image handles follow their original artwork when its index moves, and become stale when that artwork is deleted or replaced. Rollback restores the original Image identities, including handles first acquired inside the failed transaction, while handles for new/replacement artwork remain stale. PixelWall additionally retains its existing transactional guarantee for buffered direct pixel writes. Native direct `Image:clear()` pixel writes were not undone by `app.transaction` in an independent probe; the stronger PixelWall rollback guarantee is intentional.

`NewLayer` can create a grid with an in-memory origin. With no explicit bounds, the origin is the sprite grid origin modulo tile size. An explicit grid keeps its requested origin. Aseprite's file format does not persist these per-tileset origins: both native and PixelWall exports reopen them as (0,0); sprite-wide grid bounds persist separately. New tilesets copied from such a resource retain the origin in memory. An explicit `newTileset(Grid)` with a nonzero origin is still rejected, as in native Aseprite.

Not implemented: a `Sprite:newTilemap()` method (the official API uses NewLayer instead), `range.tiles`, tilemap Image storage/pixel helpers or `newCel` authoring for tilemap images, internal Tile.image.cel handles, Grid mutation, mismatched tile-image dimensions, foreign-sprite tileset assignment, automatic external-resource resolution, structural editing of a layer that uses different tilesets on different frames, and removal of a tileset still used by any layer. Unsupported access or mutation fails explicitly. Native Aseprite accepted a mismatched tile image in an independent probe and then failed while saving; PixelWall rejects that malformed grid state before mutation. The broader Image/API limitations in `lua-compatibility.md` continue to apply.

Creation/reindexing preflights both the normal sprite/storage budgets and the native vertical atlas height (at most 65,535 pixels), with tile count at most 65,536. Zero or negative dimensions and insertion/deletion indices are rejected before allocating or editing resources. The Lua cumulative temporary-pixel budget includes structural atlas work.


# Verification

`tests/fixtures/lua-tileset-create.lua` creates original RGB, indexed and grayscale sprites with three 2×2 tiles, flipped placements, a hidden layer sharing the tileset and two animation frames. `lua-tileset-oracle.lua` was run unchanged in the official Aseprite 1.3.18.5-dev source build and in PixelWall's Wasmoon VM. The adapter uses Lua 5.4.5; the oracle uses Lua 5.4.6/API 41. This is a bounded API-behavior comparison, not runtime patch-version or complete API parity.

The fixture JSON records the original native documents, native-authored expected documents and native rendered RGBA bytes. All six frames match byte-for-byte in the PixelWall renderer and when Aseprite independently reopens PixelWall's export. Tileset/tile text, color and decoded property values agree. Property binary integer widths and map key order may differ while preserving the values and namespaces.

The additional original `lua-tile-structure-create.lua`, `lua-tile-structure-oracle.lua` and `lua-tile-lifetime-oracle.lua` fixtures verify construction/copy, native linked map cels, insertion/deletion, dangling numbers, appending, Grid origins, different-size assignment, and Image lifetime. The structure script runs unchanged in both runtimes for RGB/indexed/grayscale; all six resulting frames and native reopens match byte-for-byte, and decoded metadata agrees. Additional independent probes verify copy defaults (baseIndex 1, matching flags reset) and raw-zero indexed tile initialization.

The focused tests also exercise locks and parent locks, rollback/replay, replacement handle lifetime, native/engine indexing, metadata validation, copied storage, safe deletion, external-resource refusal, large-grid preflight bounds, changing frame palettes and converted tile variants. Rectangular diagonal tile geometry is not covered by these square-tile fixtures.

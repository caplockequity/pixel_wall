# Desktop editable files

The Electron main process owns all paths and file grants. The sandbox preload exposes `window.pixelwallNativeFiles`, never generic IPC or filesystem APIs. Every IPC request must come from the owning BrowserWindow's exact main frame on `pixelwall://app/editor` (or the local index route). Browser/website users do not receive this bridge.

## Renderer integration contract

- Install `onOpen(callback)` once the host exists, then call `ready()` after device storage and document recovery load. `onOpen` receives the same result shape as `open()`: `{status:'opened'|'cancelled'|'error',files,errors}`. Each normal file is `{token,name,format,bytes}`; an already open file may be `{existingDocumentId,name,format}`. Names are display names, never paths.
- `open()` invokes the native multi-file picker. The initial OS command line, a second launch, and macOS `open-file` events enter the same queued import path. Decode `pixelwall` with the current/legacy project reader and `aseprite` with the existing codec. Preserve unsupported-format warnings. Import with a unique document ID and persist successfully before awaiting `bindOpen({token,documentId,revision})`. On every failed/cancelled import call `cancelOpen({token})`. Activate `existingDocumentId` only when there are no fresh bytes. A changed external file includes `changed:true`, `existingDocumentId`, a new token and current bytes: import as a NEW document to preserve the original recovery copy. Binding this token transfers the native path to the imported document. Cancelling keeps the original binding.
- `list()` gives all bound documents as `[{documentId,name,format,lastSavedRevision}]`. `info({documentId})` gives that record plus `status:'current'|'changed'|'unavailable'`, `pending` and optional `reason`; unknown document returns null. Renderer revisions are explicit per-document revisions, including inactive documents.
- The main process restores bindings from `native-documents.json` under app userData. Await `list()` during recovery, and explicitly save recovered native documents before close because renderer revision counters can restart. If IDB lacks a known bound document, `reopen({documentId})` returns only that previously authorized file's current bytes and a recovery token; it accepts no path. The payload adds `recovery:true`. A successful recovery may bind back to the same document ID, after persisting its recovered content. Surface failures or changed-file choices; never silently ignore a missing recovery document.
- Native desktop actions: `open` calls the native picker; `save` writes the current editable file; `saveAs` always shows the native picker. For either save action call `chooseSave({documentId,name,format,saveAs})`, expect `{status:'ready',token,format,name}`, then serialize the captured document in the **returned format**. Call `writeSave({token,documentId,revision,bytes:Uint8Array})`. Only `{status:'saved',documentId,lastSavedRevision,...}` means success. Every other result keeps artwork dirty and must be presented to the user. Call `cancelSave({token})` in a finally block if serialization or saving does not finish. `format` is `pixelwall` or `aseprite`. A picker extension determines the format; an omitted extension uses the preferred format.
- Keep document edits and switching locked during close. Save every bound dirty/native document, including inactive library documents, and preserve browser/IndexedDB saves for recovery. A browser save alone never means native success. `prepareClose(attemptId)` returns the existing ready acknowledgement plus `nativeDocuments:[{id,revision}]` for **every** bound document, exactly once. The main process compares these explicit revisions with successful native writes and checks each on-disk fingerprint again. Pending save/open grants block close. `cancelClose` retains the existing attempt cancellation semantics.
- New/unbound projects can still remain in device storage until the user chooses native Save. Native Export continues to call the existing export UI and Pro gate. Saving `.pixelwall`/`.aseprite` editables is free. The bridge provides no PNG/GIF/video export capability.

## Guarantees and limits

Save captures SHA-256, size, nanosecond mtime/ctime, device and inode. Changed/moved/deleted originals route to Save As and cannot be overwritten through that conflict flow. Saving over another open document's target is refused. Files are written and fsynced to an exclusive same-directory temporary file, checked again, then atomically renamed; a newly created destination uses a no-clobber hard-link install. The directory is flushed where supported and the resulting bytes are verified. The renderer never receives a successful acknowledgement for a cancelled/failed write. Generic filesystem errors are translated without leaking full paths.

Main-owned registry updates are serialized and atomic. Bind acknowledgements await registry persistence. A file write followed by a registry failure reports an error and cannot authorize close; retrying Save can persist the location without losing the newly written bytes. Invalid or unreadable registry data fails closed rather than silently discarding known file associations. This registry is local app state and is separate from OS extension associations.

Atomic replacement of existing files has the usual cross-process time-of-check/rename race: Node does not provide a portable filesystem compare-and-swap primitive against another application's writer. Checks occur immediately before replacement and after writing. This is not an exclusive lock against external applications. Directory fsync is unavailable on some Windows/filesystem combinations. A hard-link-incompatible filesystem may reject first save; that failure keeps the window open rather than falling back to an unsafe partial write.

Files are limited to 64 MiB and native editables only. Codec validation and preservation remain the renderer's responsibility. No new association handler follows external asset references from Aseprite files. Packaging declares Editor associations for `.pixelwall` and `.aseprite`; actual OS registration requires installing the rebuilt application. Installer/OS behavior has not been verified by these unit tests.

# Local desktop MCP

Current PixelWall packaged desktop builds include an MCP launcher for a running PixelWall desktop window. The connection is local to the computer and is closed by default. It does not provide a cloud API or send artwork to PixelWall servers. Anonymous app-health and agent-operation reporting is enabled by default in current packaged builds and can be declined or disabled from Help; it does not require opening an MCP connection. The first MCP connection still presents the reporting disclosure when the local connection is enabled.

Open the desktop app’s Help menu and enable **Allow local agent connection**. Choose the export folder when prompted. PixelWall shows the approved folder and the launcher command:

```sh
node pixelwall-mcp.mjs
```

Configure your MCP client to run that command from the unpacked CLI download. The launcher reads the authenticated session file created by PixelWall and speaks the official MCP stdio transport. The session is limited to the open editor window and one controller at a time. Disable the same Help-menu option, close the window, or stop the MCP client to disconnect.

The server discovers the current `window.pixelwall` tool metadata at runtime. It supports document inspection, project selection and import, command validation and application, progress polling and cancellation, preview capture, undo and redo, saving, export handoff, and durable artifact listing and reading. `pixelwall_save_artifact` writes a verified artifact into the folder selected in PixelWall; an MCP client cannot choose an arbitrary filesystem directory. Generated files are temporary local handoff records: they expire after 24 hours and the store retains at most 64 files or 128 MiB total, with a 64 MiB per-file limit. `pixelwall_read_artifact` returns at most a 1 MiB chunk and includes checksum metadata for verification.

For large edits, use `wait: false`, poll the returned operation with `pixelwall_operation`, and use `pixelwall_cancel` when needed. A completed operation reports its revision and command count. Cancellation is checked between commands; it is not a promise about the runtime of an individual command. A failed or disconnected operation does not commit partial artwork. Use a unique `requestKey` when a caller may retry the same apply call: an identical retry reuses the retained result in that editor session, while a mismatched or expired key is rejected so an agent can inspect before deciding whether to start a new edit.

The launcher requires Node.js 22.13 or newer. This integration controls a running local desktop window only. It is unavailable to hosted browser sessions and does not accept remote connections.

The Help menu's **Share anonymous app and MCP usage** setting is independent from **Allow local agent connection**. It controls anonymous desktop app-health and agent-operation reporting; health events can be emitted on launch or update even when MCP is never opened. Before the first connection, PixelWall explains that reports contain only bounded lifecycle/operation and result categories, app version, platform, architecture, duration bucket, local `usage_day` (`first` or `returning`), and limited preview or artifact-persistence categories. Reports never contain artwork, file paths, file contents, IDs, agent names, raw arguments, email, or error text. Turning the setting off cancels pending reports and preserves the refusal; corrupt settings fail closed. The app keeps no offline queue and does not backfill earlier activity. Operations are action counts; `first` means the first reporting day observed by that installation, not first install, and `returning` means a later reporting day. Neither identifies unique users, retention, verified agents, or a linked funnel. The local CLI, standalone editor, and hosted browser telemetry use separate reporting paths.

The packaged CLI uses the same bounded reporting model through `cli_usage_counted`, adding the operation, format, duration bucket, `wrote_files`, and `verified` where applicable. It is enabled by default in packaged builds and can be disabled with `--no-telemetry`, `PIXELWALL_TELEMETRY_DISABLED=1`, or `DO_NOT_TRACK=1`; its telemetry status and enable/disable controls are also available from the CLI. CLI and desktop preferences are local to each installation and are not a customer identity. Packaged CLI reporting and default-on desktop MCP reporting began in 0.6.2; earlier desktop releases may offer opt-in MCP reporting. App-health reporting begins in 0.6.4 and does not prove a download or installation was completed.
